# Commercial Tracking Power BI Report Kit

This kit defines a read-only Power BI reporting and manifest-printing solution over the SharePoint `Tracking` list. It is designed for logistics operations, daily accountability, printable manifests, PDF archiving, and Excel/CSV export.

## Recommended Report

Build two pages in Power BI Desktop and one paginated report:

1. **Daily Operations** — interactive overview for logistics personnel.
2. **Manifest Finder** — locate a Manifest ID, recipient, location, or receiving date.
3. **Commercial Tracking Manifest.rdl** — authoritative print surface with repeating headers and complete pagination.

Use only Microsoft-native visuals. Avoid custom visuals so PDF export remains supported and the approval footprint stays small.

## Files

- `TrackingQuery.pq` — Power Query M query for the SharePoint list.
- `Measures.dax` — calculated columns and report measures.
- `CommercialTrackingTheme.json` — semantic colors matching the Power App.
- `VISUAL_LAYOUT.md` — exact page and visual configuration.
- `PAGINATED_MANIFEST.md` — Report Builder construction and print workflow.
- `PaginatedDataset.dax` — parameterized dataset query for the manifest report.

## Connect the Data

1. Open Power BI Desktop.
2. Select **Transform data > New source > Blank query**.
3. Open **Advanced Editor** and paste `TrackingQuery.pq`.
4. Create these Power Query parameters before applying the query:

   | Parameter | Type | Example |
   |---|---|---|
   | `SiteUrl` | Text | `https://tenant.sharepoint.com/sites/Logistics` |
   | `TrackingListName` | Text | `Tracking` |
   | `ReportUtcOffsetHours` | Decimal number | `-7` for PDT or `-8` for PST |

5. Sign in with **Organizational account** when prompted.
6. Confirm the query returns the expected list and columns.
7. Rename the query to `Tracking`.
8. Apply changes.

The query uses SharePoint connector implementation 2.0 and reads the full list schema. It does not write to SharePoint.

## Add the Model Logic

Create the calculated columns first, followed by the measures, using `Measures.dax`. Keep all timestamps in the generated `... Local` columns for report filters and display.

Mark `Received Date` as a date column. Sort `Location Sort` by itself and use it to sort the displayed `Location` field when a fixed operational order is desired.

## Apply the Theme

Select **View > Themes > Browse for themes** and import `CommercialTrackingTheme.json`.

The report uses the same semantic pattern as the Power App:

- Blue — primary information
- Green — completed or successfully received
- Amber — attention required
- Red — errors, voids, or stop conditions
- Gray — neutral context

Text labels remain present; color is never the only indicator.

## Data Protection

- Publish only to the approved organizational workspace.
- Grant consumers Viewer/read access through approved organizational groups.
- Do not use **Publish to web**.
- Apply the MTF-approved sensitivity label before distribution or export.
- Confirm exported files are stored only in approved locations.
- Keep Notes off the printable detail page because it contains optional human-entered operational context and makes the output difficult to scan.

## Refresh

For an operational report, start with scheduled refresh every 30–60 minutes during receiving hours. If near-real-time visibility is required, confirm capacity and tenant policy before increasing refresh frequency.

## Manifest Printing Workflow

The Power BI report should expose a prominent **Print Manifest** button on the Manifest Finder page. Configure it as a Web URL action that opens the published paginated report. Staff then select:

- Manifest ID for an exact manifest already generated by the Power App;
- receiving date and optional location for a daily inbound manifest; or
- recipient and date range for a custody report.

The paginated report is the print authority because it prints every matching row, repeats column headers, numbers pages, and exports cleanly to PDF or Excel.

The standard Power BI table remains a preview and search surface. A scrollbar is not converted into additional PDF pages, so do not use the ordinary table visual as the archival printout.

## Audit Boundary

Power BI is read-only and cannot update `ManifestPrintedBy` or SharePoint modification metadata. For an exact audited manifest:

1. Generate the manifest in the Power App first so the included records receive a `ManifestID`.
2. Use Manifest Finder to select that `ManifestID`.
3. Print or reprint the exact set through the paginated report.

Daily and recipient reports that are assembled only in Power BI are reporting extracts, not new audited manifest records. Their header must say **Reporting Extract** unless every row shares a nonblank Manifest ID.
